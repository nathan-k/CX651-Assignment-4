(1) In plot-single.png each run had the entire machine to itself. A 500x500 multiply took about 0.36 seconds at roughly 98% CPU. In plot-multi.png, ten 500x500 multiplies started at the same time. Each one took about 3.3 seconds. This is nearly 10x slower, while CPU utilization was around 16% per process. They were competing for 2 CPUs, with the scheduler time-slicing between them.

(2) In plot-taskset.png, all ten processes were run on CPU 0. Each run took about 3.6 seconds and had around 10% CPU utilization, while the runs in plot-multi.png took about 3.3 seconds and 16% CPU utilization. Pinning removes the scheduler's option to spread the processes across both CPUs, so all ten share one core. The slowdown was small because both virtual cores appear to share the same physical hardware.

(3) In plot-nice.png, the ten runs had niceness starting at 0 and going up to 19. Unlike plot-multi.png where every process was treated equally and both lines are flat, the lines now slope with priority. CPU utilization falls from 50% for the nice 0 run to 12% for the nice 19 run, and multiply time rises from 1.1s to about 2.8s. This is because processes with lower niceness get a larger share of CPU time.
